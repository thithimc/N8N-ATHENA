# Consignes de communication

## Alerter uniquement en cas de problème

Ne notifier l'utilisateur (tmchevaleraud@gmail.com) **que lorsqu'il y a un vrai
problème** à signaler. Rester silencieux le reste du temps.

**Ne PAS envoyer** de messages du type « rien à signaler », « tout est OK »,
« aucune action requise », « prochain contrôle reprogrammé », etc.

**Envoyer une alerte** uniquement pour un souci réel, par exemple :
- une CI qui échoue / un check rouge ;
- un conflit de merge sur une PR ;
- un commentaire de review qui demande une action ;
- une erreur d'exécution, un workflow cassé, un test qui échoue ;
- tout blocage empêchant d'avancer.

Cela vaut pour les **check-in automatiques** (self check-in sur les PR) : si
rien n'a changé, reprogrammer le prochain check-in **en silence**, sans écrire à
l'utilisateur. Ne parler que si le check-in révèle un problème.

Le travail demandé explicitement par l'utilisateur reçoit évidemment une réponse
normale — cette règle concerne les notifications proactives et les comptes rendus
de surveillance.
